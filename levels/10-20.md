# Level 10 -> Level 11

### Goal
Retrieve the password stored in `data.txt`, which is base64-encoded text.

### Commands Used
- `ls`
- `file`
- `base64`

### Walkthrough
1. Log in to `bandit10`:
```bash
   ssh bandit10@bandit.labs.overthewire.org -p 2220
```
Check the file type to confirm its format:
```bash
bandit10@bandit:~$ file data.txt
data.txt: ASCII text
```
Decode the base64 content to reveal the plaintext password:
```bash
bandit10@bandit:~$ base64 -d data.txt
The password is PASSWORD_HERE
```
>[!TIP]
>Base64 is an encoding scheme used to represent binary data in ASCII string format. The -d (or --decode) flag tells the base64 utility to decode the input rather than encode it.

# Level 11 -> Level 12

### Goal
Retrieve the password stored in `data.txt`, where all lowercase and uppercase letters have been rotated by 13 positions (ROT13).

### Commands Used
- `ls`
- `cat`
- `tr`

### Walkthrough
1. Log in to `bandit11`:
```bash
   ssh bandit11@bandit.labs.overthewire.org -p 2220
```
Decode the ROT13 cipher using tr to translate characters from A-Za-z to N-ZA-Mn-za-m:
```bash
bandit11@bandit:~$ cat data.txt | tr 'A-Za-z' 'N-ZA-Mn-za-m'
The password is PASSWORD_HERE
```
>[!TIP]
>ROT13 is a simple substitution cipher that replaces a letter with the 13th letter after it in the alphabet. Running tr with matching set ranges handles both uppercase and lowercase shifts in a single pipeline.

# Level 12 -> Level 13

### Goal
Retrieve the password stored in `data.txt`, which has been repeatedly compressed using different file formats and hex-dumped.

### Commands Used
- `mktemp`
- `cp`
- `xxd`
- `file`
- `gzip`
- `bzip2`
- `tar`
- `cat`

### Walkthrough
1. Log in to `bandit12`:
```bash
ssh bandit12@bandit.labs.overthewire.org -p 2220
```
Create a temporary directory in /tmp and copy data.txt to it to work safely:
```bash
bandit12@bandit:~$ mktemp -d
/tmp/tmp.eIh6S1cQdn
bandit12@bandit:~$ cp data.txt /tmp/tmp.eIh6S1cQdn
bandit12@bandit:~$ cd /tmp/tmp.eIh6S1cQdn
```
Reverse the original hexdump using xxd:
```bash
bandit12@bandit:/tmp/tmp.eIh6S1cQdn$ xxd -r data.txt > compressed
```
Iteratively inspect the file type using file, rename with the corresponding extension (.gz, .bz2, .tar), and decompress using the appropriate tool:
gzip: mv file file.gz => gzip -d file.
gzbzip2: mv file file.bz2 => bzip2 -d file.
bz2tar: tar -xf file

Once decompressed down to plain ASCII text, read the final file (data8):
```bash
bandit12@bandit:/tmp/tmp.eIh6S1cQdn$ cat data8
The password is PASSWORD_HERE
```
>[!TIP]
>The xxd -r command converts a hex dump back into binary data. Since archive formats like gzip and bzip2 require specific extensions to decompress via their CLI tools, using file at each layer reveals the correct compression format.

# Level 13 -> Level 14

### Goal
Retrieve the password for `bandit14` by authenticating via SSH using a private key stored in `sshkey.private`.

### Commands Used
- `ls`
- `cat`
- `ssh`

### Walkthrough
1. Log in to `bandit13`:
```bash
   ssh bandit13@bandit.labs.overthewire.org -p 2220
```
Locate the SSH private key in the home directory:
```bash
bandit13@bandit:~$ ls
HINT  sshkey.private
```
Use the private key to log into bandit14 directly on localhost:
```bash
bandit13@bandit:~$ ssh -i sshkey.private bandit14@localhost -p 2220
```
(Alternatively, copy the key locally to your machine, grant appropriate permissions chmod 600, and connect).

Once logged in as bandit14, read the level password from /etc/bandit_pass/bandit14:
```bash
bandit14@bandit:~$ cat /etc/bandit_pass/bandit14
PASSWORD_HERE
```
>[!TIP]
>SSH private keys allow passwordless authentication. When using custom keys, SSH requires strict file permissions (typically chmod 600) to prevent other users from reading sensitive key material.

# Level 14 -> Level 15

### Goal
Retrieve the password for the next level by submitting the current level's password to a service running on port 30000 on `localhost`.

### Commands Used
- `cat`
- `nc`

### Walkthrough
1. Log in to `bandit14`:
```bash
ssh bandit14@bandit.labs.overthewire.org -p 2220
```
Retrieve the current password for bandit14 so you can submit it to the service:
```bash
bandit14@bandit:~$ cat /etc/bandit_pass/bandit14
aaWecNkG4FhxJQxz07uiwzVP6bJiYS65
```
Connect to the local service on port 30000 using Netcat (nc) and paste the password:
```bash
bandit14@bandit:~$ nc -nv 127.0.0.1 30000
Connection to 127.0.0.1 30000 port [tcp/*] succeeded!
aaWecNkG4FhxJQxz07uiwzVP6bJiYS65
Correct!
PASSWORD_HERE
```
>[!TIP]
>Netcat (nc) is often referred to as the "Swiss Army knife" of networking. It is used to read from and write to network connections. The -n flag prevents DNS resolution (speeding up local connections), and -v provides verbose output so you know when the connection succeeds.
