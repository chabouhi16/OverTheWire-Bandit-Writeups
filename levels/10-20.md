# Level 10 -> Level 11

### Goal
Retrieve the password stored in `data.txt`, which is base64-encoded text.

### Commands Used
- `ls`
- `file`
- `base64`

### Walkthrough
1. Log in to `bandit10`:
```bash
   ssh bandit10@bandit.labs.overthewire.org -p 2220
```
Check the file type to confirm its format:
```bash
bandit10@bandit:~$ file data.txt
data.txt: ASCII text
```
Decode the base64 content to reveal the plaintext password:
```bash
bandit10@bandit:~$ base64 -d data.txt
The password is PASSWORD_HERE
```
>[!TIP]
>Base64 is an encoding scheme used to represent binary data in ASCII string format. The -d (or --decode) flag tells the base64 utility to decode the input rather than encode it.

# Level 12 -> Level 13

### Goal
Retrieve the password stored in `data.txt`, which has been repeatedly compressed using different file formats and hex-dumped.

### Commands Used
- `mktemp`
- `cp`
- `xxd`
- `file`
- `gzip`
- `bzip2`
- `tar`
- `cat`

### Walkthrough
1. Log in to `bandit12`:
```bash
ssh bandit12@bandit.labs.overthewire.org -p 2220
```
Create a temporary directory in /tmp and copy data.txt to it to work safely:
```bash
bandit12@bandit:~$ mktemp -d
/tmp/tmp.eIh6S1cQdn
bandit12@bandit:~$ cp data.txt /tmp/tmp.eIh6S1cQdn
bandit12@bandit:~$ cd /tmp/tmp.eIh6S1cQdn
```
Reverse the original hexdump using xxd:
```bash
bandit12@bandit:/tmp/tmp.eIh6S1cQdn$ xxd -r data.txt > compressed
```
Iteratively inspect the file type using file, rename with the corresponding extension (.gz, .bz2, .tar), and decompress using the appropriate tool:
gzip: mv file file.gz => gzip -d file.
gzbzip2: mv file file.bz2 => bzip2 -d file.
bz2tar: tar -xf file

Once decompressed down to plain ASCII text, read the final file (data8):
```bash
bandit12@bandit:/tmp/tmp.eIh6S1cQdn$ cat data8
The password is PASSWORD_HERE
```
>[!TIP]
>The xxd -r command converts a hex dump back into binary data. Since archive formats like gzip and bzip2 require specific extensions to decompress via their CLI tools, using file at each layer reveals the correct compression format.

# Level 16 -> Level 17

### Goal
Locate the open SSL port in the range 31000-32000, submit the current level password, and retrieve the private SSH key for `bandit17`.

### Commands Used
- `nmap`
- `openssl s_client`
- `ssh`

### Walkthrough
1. Log in to `bandit16`:
```bash
ssh bandit16@bandit.labs.overthewire.org -p 2220
```
Scan the port range 31000-32000 on 127.0.0.1 using nmap with SSL certificate detection to locate the correct SSL-listening service:
```bash
bandit16@bandit:~$ nmap --script ssl-cert -p 31000-32000 127.0.0.1
```
Pipe the password from /etc/bandit_pass/bandit16 into OpenSSL connected to the correct TLS port (31790):
```bash
bandit16@bandit:~$ cat /etc/bandit_pass/bandit16 | openssl s_client -quiet -connect 127.0.0.1:31790
```
The server responds with an RSA private SSH key.

Save the returned RSA private key into a local file, restrict permissions (chmod 600), and authenticate as bandit17:
```bash
bandit16@bandit:~$ chmod 600 ssh.private
bandit16@bandit:~$ ssh bandit17@bandit.labs.overthewire.org -i ssh.private -p 2220
```
>[!TIP]
>nmap --script ssl-cert allows you to differentiate standard plain-text services from SSL/TLS services by reading their certificates. Using -quiet with openssl s_client strips out handshake telemetry, leaving only raw payload output.
