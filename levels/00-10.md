# Level 00 -> Level 01

### Goal
Log in to the game server via SSH and retrieve the password stored in a file named `readme` in the home directory.

### Commands Used
- `ssh`
- `ls`
- `cat`

### Walkthrough
1. Connect to the OverTheWire Bandit server:
```bash
ssh bandit0@bandit.labs.overthewire.org -p 2220
```
2. Password used:
```bash
bandit0.
```
List directory contents and read the target file:
```bash
bandit0@bandit:~$ ls
readme
bandit0@bandit:~$ cat readme
PASSWORD_HERE
```
>[!NOTE]
>Basic SSH authentication and reading standard text files.

# Level 03 -> Level 04
### Goal
Retrieve the password stored in a hidden file inside the inhere directory.
-`ls`
-`cd`
-`cat`
### Walkthrough
Log in to bandit3.
```bash
ssh bandit3@bandit.labs.overthewire.org -p 2220
```
Navigate into the target directory:
```bash
bandit3@bandit:~$ cd inhere/
```
Standard ls shows no files. Use the -a flag with ls to display all hidden files (files starting with a dot .):
```bash
bandit3@bandit:~/inhere$ ls -lah
total 12K
drwxr-xr-x 2 root    root    4.0K Jun 24 14:59 .
drwxr-xr-x 3 root    root    4.0K Jun 24 14:59 ..
-rw-r----- 1 bandit4 bandit3   33 Jun 24 14:59 ...Hiding-From-You
```
Read the hidden file:
```bash
bandit3@bandit:~/inhere$ cat ./"...Hiding-From-You"
PASSWORD_HERE
```
>[!NOTE]
>In Linux, files and directories that begin with a dot (.) are hidden by default. The ls -a (or ls -lah) command reveals these hidden entities.

# Level 04 -> Level 05

### Goal
Retrieve the password stored in the only human-readable file within the `inhere` directory.

### Commands Used
- `ls`
- `cd`
- `file`
- `cat`

### Walkthrough
1. Log in to `bandit4`:
```bash
ssh bandit4@bandit.labs.overthewire.org -p 2220
```
Navigate into the target directory and list the files:
```bash
bandit4@bandit:~$ cd inhere
bandit4@bandit:~/inhere$ ls
-file00  -file01  -file02  -file03  -file04  -file05  -file06  -file07  -file08  -file09
```
Use the file command with a wildcard (*) to determine the data type of every file in the directory:
```bash
bandit4@bandit:~/inhere$ file ./*
./-file00: data
./-file01: data
./-file02: OpenPGP Secret Key
./-file03: data
./-file04: data
./-file05: data
./-file06: Non-ISO extended-ASCII text, with NEL line terminators
./-file07: ASCII text
./-file08: data
./-file09: data
```
Read the contents of the human-readable file (-file07):
```bash
bandit4@bandit:~/inhere$ cat ./"-file07"
PASSWORD_HERE
```
>[!TIP]
>The file command analyzes a file's contents to determine its type, regardless of its extension. Using ./* passes all files in the current directory as arguments while simultaneously preventing files starting with a dash (-) from being misinterpreted as command options

# Level 05 -> Level 06

### Goal
Retrieve the password stored in a file under the `inhere` directory that matches specific properties: human-readable, 1033 bytes in size, and not executable.

### Commands Used
- `ls`
- `cd`
- `find`
- `cat`

### Walkthrough
1. Log in to `bandit5`:
```bash
ssh bandit5@bandit.labs.overthewire.org -p 2220
```
Navigate into the inhere directory and inspect the structure (multiple subdirectories present):
```bash
bandit5@bandit:~$ cd inhere/
```
Use find to search recursively for a file with an exact size of 1033 bytes (1033c):
```bash
bandit5@bandit:~/inhere$ find -size 1033c
./maybehere07/.file2
```
Navigate to the directory containing the located file and verify its contents:
```bash
bandit5@bandit:~/inhere$ cd maybehere07
bandit5@bandit:~/inhere/maybehere07$ cat .file2
PASSWORD_HERE
```
>[!TIP]
>The find command is ideal for searching complex directory trees. Specifying -size 1033c filters for files of exactly 1033 bytes (c stands for bytes), making it easy to isolate the exact target without checking every subfolder manually.

# Level 06 -> Level 07

### Goal
Retrieve the password stored somewhere on the server that belongs to user `bandit7`, group `bandit6`, and is 33 bytes in size.

### Commands Used
- `cd`
- `find`
- `cat`

### Walkthrough
1. Log in to `bandit6`:
```bash
   ssh bandit6@bandit.labs.overthewire.org -p 2220
```
Search the entire filesystem from the root directory (/) matching the specific user, group, and file size criteria:
```bash
bandit6@bandit:~$ cd /
bandit6@bandit:/$ find -user bandit7 -group bandit6 -size 33c 2>/dev/null
/var/lib/dpkg/info/bandit7.password
```
Read the located file to retrieve the password:
```bash
bandit6@bandit:/$ cat /var/lib/dpkg/info/bandit7.password
PASSWORD_HERE
```
>[!TIP]
>Redirecting standard error to /dev/null using 2>/dev/null suppresses all "Permission denied" noise from find, allowing you to see only the actual file path found.

# Level 08 -> Level 09

### Goal
Retrieve the password stored in the file `data.txt`, which is the only line of text that occurs only once.

### Commands Used
- `ls`
- `sort`
- `uniq`

### Walkthrough
1. Log in to `bandit8`:
```bash
   ssh bandit8@bandit.labs.overthewire.org -p 2220
```
Sort the lines in data.txt and filter for the unique line using uniq -u:
```bash
bandit8@bandit:~$ sort data.txt | uniq -u
PASSWORD_HERE
```
>[!TIP]
>The uniq command requires sorted input to work properly because it only compares adjacent lines. Piping the output of sort into uniq -u isolates lines that appear exactly once.

# Level 09 -> Level 10

### Goal
Retrieve the password stored in `data.txt` inside one of the few human-readable strings, preceded by several `=` characters.

### Commands Used
- `ls`
- `strings`
- `grep`

### Walkthrough
1. Log in to `bandit9`:
```bash
   ssh bandit9@bandit.labs.overthewire.org -p 2220
```
Extract printable character sequences from the binary file using strings and search for = characters using grep:
```bash
bandit9@bandit:~$ strings data.txt | grep "="
========== the
========== password
========== is
========== PASSWORD_HERE
```
>[!TIP]
>The strings command extracts sequences of printable characters from binary or unreadable files. Combining it with grep "=" filters out noise and quickly locates structured flag headers like ==========.
